# Decisions

Standing owner decisions not visible in code; one line each. Superseded lines are replaced.

- Targets in priority order: macOS (Apple Silicon), Android TV, iPhone/iPad; Linux desktop is the dev/test platform and supported; Android phone ships with Android; no Windows, no tvOS.
- Apple minimums: iOS/iPadOS 26.0 and macOS 26.0 on Apple Silicon only (no Intel build); 27 once `macos-latest` runs macOS 27.
- Stack: Flutter stable (pinned in `app/FLUTTER_VERSION`) + media_kit (libmpv everywhere) + a Rust core through flutter_rust_bridge v2.
- Standalone apps now, a home hub later: every device runs the full core; user data uses stable content keys and `updated_at` so a hub can sync it later.
- Crates: `gerdtv-core` (all logic), `gerdtv-api` (bridge surface only; package `gerdtv_api` because Cargokit names the native library after it), `gerdtv-testkit`, `gerdtv-release`, `gerdtv-host` (the headless host and its web player).
- Player libraries (Spike A): media_kit 1.2.6 with the upstream `media_kit_libs_video` packages on every platform, pinned to exact versions; media_kit_video 2.0.1 vendored in `third_party/` and patched (Apple: libmpv looked up at run time), not forked on GitHub.
- Playback ends only by Stop or by starting another stream; leaving the player keeps it running (now-playing bar, floating mini player, background playback).
- Floating/background playback: desktop floating always-on-top window, Android system Picture-in-Picture with a foreground service, Apple Picture-in-Picture without a hand-over (swiping to Home starts it on iOS); leaving the app floats only what really plays.
- Lock screen: the system's Now Playing card with play/pause only, no Live Activity (its extension needs a second app ID to re-sign).
- Apple platforms: mpv plays everything by default (its own frames feed iOS PiP); AVPlayer over the core's local HLS is a Settings choice for live, applied at the next start.
- Own libmpv builds for all platforms, bundled next to media_kit's, switchable in Settings (restart).
- Channel lists: four display modes (compact list, list, tiles, large tiles) per section, with a quick toggle in the list bar.
- One TV section (lists or guide, switched and remembered); Premiumize is a section after Series while linked; a long hold on a channel, movie, series or group opens a menu.
- Guide: grid, now/next in every list, mini-guide in the player, catch-up and reminders; 2 days back, 7 ahead (3 on phone/TV).
- Reminders as system notifications via flutter_local_notifications 22.3.3 (23.x needs compileSdk 37) and timezone, 5 minutes ahead.
- The guide's header is never empty: before a programme is focused it shows the first row's running programme.
- Sort: provider order by default; groups by name, items also by number (live), year, date added and rating (movies, series); remembered per section; continue watching, episodes and search keep their own order.
- Favourites: a Favourites group on top of each section's groups, in the section's item order; toggled by a star on every row and tile, the menu behind a long press or a long OK.
- Swipe on phones: from the left edge back, sideways between sections (not on the guide), and in the player media_kit's seek, volume and brightness swipes (the player's volume; brightness on the left half; switchable).
- Theme: dark by default, or light or the system's; orange by default among eight accent presets; neutral surfaces by default (tinted on request); pure black on request; app-wide.
- Settings in five categories: Account (with Your data), Playback (with Stream health), TV guide, Appearance, About (with Updates).
- Profiles: added and switched in Settings → Account; with several, a start picker that remembers the last one and offers "Always open this one".
- Hidden groups instead of PIN-locked ones: ticked in Settings → Appearance → Hidden groups, gone everywhere (lists, search, guide, favourites, continue watching); no PIN.
- Continue watching: a row on top of Movies and Series; started after 2 min, finished at 95 %; opening a movie or episode continues where it was left.
- Debrid: Premiumize's own cloud as a source (folders, transfers, play), linked per profile with the API key or a device code with the user's own client id; no torrent search.
- Watch tracking: Trakt and Simkl by scrobbling (start, pause, stop with progress), linked by device code; no client id or secret in the repository or the builds: every service (Trakt, Simkl, Premiumize's code login) with the user's own app, entered in Settings.
- Trailers: the panel's YouTube trailer in YouTube's embed (webview_flutter), muted behind a movie's or series' title after 2 s, with sound from the Trailer button; movies open a page before playing (Continue watching plays at once).
- Search lives in each section, not in a tab of its own: a section's group list searches the whole section, a group only itself with an All groups chip; both TV views list channels, then live and upcoming programmes (the guide's search can be limited to its shown group).
- Voice search on Android only, through a mic in the search field and the system's speech recognizer; the remote's own voice key stays with the system.
- Search ranking: tiers (word starts, group name, mid-word, typos from 4 letters), favourites and recents first within each tier; a tier is searched only when the better ones don't fill the page, so a search stays as fast as a plain word search (bench gate); typing anywhere starts the search.
- Programme search: Live now, then Upcoming (each with its own limit); ended programmes only on "Show earlier"; programmes also match by their channel's name.
- macOS runs without the app sandbox (the updater swaps the bundle in place); the old container's data is copied over once, never moved.
- macOS menu bar mode, on by default and switchable: closing or quitting from the Dock hides gerdTV into the menu bar; built natively in Swift (no tray_manager).
- Desktop mini player (Spike B): the main window shrinks into a borderless, always-on-top window (window_manager's native API), so the same engine and player keep playing; no second window.
- Desktop player window: the content keeps the picture's aspect ratio while the player shows (resizing too); browsing and player sizes are remembered separately, with an animated switch.
- Desktop window minimum: outside the player 960 × 540 content, so the desktop layout (rail) always stays; the player and the mini player may be smaller.
- The playback watchdog is a pure Rust state machine; a small Dart adapter feeds it mpv events and runs its commands.
- Pre-approved Rust deps: tokio, reqwest (rustls, gzip, stream), serde/serde_json, quick-xml, flate2, lzma-rust2 (xz guides), rusqlite (bundled, FTS5), tracing (+ subscriber, appender), thiserror, one of time/chrono, mdns-sd, one Google Cast crate (Spike C), chacha20poly1305, spake2 and qrcode (device pairing), flutter_rust_bridge, ed25519-dalek + sha2, criterion (dev), libmpv2 (dev, testkit only).
- Pre-approved Dart deps: media_kit (+ media_kit_video and the chosen libs packages), flutter_rust_bridge, path_provider, flutter_secure_storage, window_manager, tray_manager, launch_at_startup, flutter_local_notifications, file_selector and share_plus (Settings → Account → Your data), webview_flutter with its Android and WebKit packages (trailers), flutter_lints; plus Flutter's first-party flutter_localizations, intl (required by gen-l10n), material_ui (Material moved out of the SDK) and cupertino_ui (its Cupertino counterpart, pulled in by material_ui; used for the phones' swipe-back slide).
- Devices & sync: two installs pair on the local network with no server (a QR or a typed 6-digit code made safe by SPAKE2, one attempt, 10 minutes; the system camera's `gerdtv://` link on phones, no camera library); everything travels sealed (provider login, linked services, TMDB and OpenSubtitles keys, user data), both ways, newer wins; remembered devices sync by hand (Sync now), and gerdTV listens for them while it runs.
- Web player: served by a headless gerdTV host on the owner's own machine (not by the apps), reached through the owner's tunnel: an HTTPS front door for one-time login links from a paired app, a plain-HTTP player page that plays the provider's http:// streams directly; no relay (a stream the browser can't play says so); sessions 3 h, extendable by 3 h; the browser never gets the login as text; plain HTML/JS page with the desktop look, hls.js only for browsers without built-in HLS.
- Host updates: the host updates itself (`gerdtv-host update`, nightly by a root timer the owner enables) from the signed `latest.json`, keeping the old binary for an automatic rollback; a VM snapshot is the owner's `--before` command, not code in the repo.
- First run can be skipped: without a provider all of Settings works and only initialised sections show; the provider's login is edited in Settings → Account and replaces the old one only once it works.
- User data export: the open profile only, no secrets; import merges row by row (newer `updated_at` wins, nothing is deleted).
- Benchmarks compare A/B in one run (origin/main's core, then the branch's), not against a stored baseline.
- Own libmpv: one self-contained library per platform (mpv + FFmpeg + libplacebo, LGPL), built by our scripts in CI, named libgerdmpv; media_kit's engine stays the default until ours passes the harness, the journeys and the owner's device checks.
- Linux CI runs the integration tests on gerdTV's own libmpv only (no Lua scripts to deadlock media_kit's start); the standard engine keeps the libmpv harness.
- State management with `ChangeNotifier`/`ValueListenable`, navigation with `Navigator`/`Router`; images fetched and disk-cached by the core, shown with `Image.file`.
- Native code only as small, commented Swift/Kotlin platform channels; no third-party native libraries.
- Android renders with Skia over OpenGL ES (Impeller off): Impeller's Vulkan path garbles the Shield's picture; retest when Flutter removes the switch.
- The Rust bridge is integrated with Cargokit (flutter_rust_bridge's default backend), not Dart native-assets hooks.
- Xtream Codes lists are fetched in full (one call per kind, measured at under 2 s each on a 20k-entry account), not per category.
- Sources: Xtream Codes first, M3U/M3U8 as fallback, any number of XMLTV URLs per profile; where guides overlap the provider's wins.
- Missing guide data: community presets (epgshare01, free-epg, Rytec over plain HTTP as the one exception, Pluto TV, Samsung TV Plus, open-epg; third parties), none added by default; names match within a country (DE/AT/CH share), no automatic fuzzy matching, suggestions need a tap; programmes only for channels the profile has.
- TMDB: opt-in with the user's own key (app-wide), asked per page and cached 30 days; attribution with TMDB's logo as a PNG rendered from its SVG (no SVG package).
- OpenSubtitles: opt-in with the user's own key and optional login (app-wide); subtitles load into mpv only (not Apple's player).
- Secrets (provider credentials, TMDB key, OpenSubtitles key and login, linked services' tokens per profile: Premiumize, Trakt, Simkl) live in `flutter_secure_storage` (macOS: the login keychain through Apple's `security` tool, so updates don't ask for the keychain password, accepting that any of the user's programs can ask the tool too; Developer ID is a possible later step), are held only in memory by the core, never in logs.
- Google Cast crate: oxicast, wrapped behind gerdTV's own interface; no fake Cast receiver in the test kit (no extra TLS/protobuf test dependencies): Cast is checked by hand on the Shield, and only gerdTV's own logic around oxicast is unit-tested.
- Casting: Google Cast from every platform in the core (oxicast pinned exactly; the provider's address first, gerdTV's local HLS as live's fallback); AirPlay from Apple platforms via AVKit/AVPlayer, not built yet: it needs the local HLS on the network address while AirPlay is active (a [MAC] session with a receiver).
- Recording in the core as direct stream capture; desktop while the app runs (also menu-bar/tray only), Android via the foreground service while gerdTV runs and, closed, an exact-alarm notification that starts it when opened (a start by the alarm alone waits for a device check); none on iOS; 2 min lead, 10 min lag; at the account's limit the recording wins after a notice with Skip.
- CI only on GitHub's free standard runners (`ubuntu-latest`, `macos-latest`); no self-hosted or larger runners.
- One branch and PR per session, features as commits, the wrap-up as its last commit; CI runs only the areas a change touches; the draft PR is opened only once `just ready` is green (branch pushes start no CI), the wrap-up pushed right after.
- macOS releases ship a DMG for the first install and keep the zip for the in-app updater.
- Releases: one per wrap-up from `release.yml`; macOS signed with a stable self-signed certificate; Android with the release keystore; an unsigned iOS IPA; a signed `latest.json` for the in-app updater.
- No automated installs on the owner's devices; the owner installs every first copy.
- The logo is drawn in code, the user picks it in Settings, and the pick switches the launcher icon on Android and iOS and the Dock or window icon on macOS and Linux.
- Look: cinematic (edge-to-edge posters, a blurred backdrop for series, tiles lift on focus, skeleton loading, pictures fade in); motion about 220 ms: wide windows fade with a slight zoom, phones slide with swipe-back, none with reduced motion.
- Android has no cleartext network config: nothing in the app uses Android's HTTP stack (libmpv and the core bring their own).
- UI strings in English and German via gen-l10n; the UI follows the system language; the name is spelled "gerdTV" everywhere visible.
