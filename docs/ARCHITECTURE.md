# Architecture

## Crates
- `crates/gerdtv-core`: all logic, no Flutter dependency, tested headless on Linux.
  - `epg.rs`: the guide: streaming XMLTV parser (quick-xml; gzip detected by its magic bytes), import per source in one transaction (a source replaces its own rows; sources rank the provider's guide first, then extra ones in the order added: a channel a higher-ranked source fills is skipped and a lower-ranked schedule for it removed; only the window is stored), matching (manual map → id → id ignoring case → normalised display name → a twin item of the same normalised name; the automatic steps only take guide channels that have programmes, a shared name the highest-ranked source's), and the queries for now/next, the grid window, programme details, programme search and the mapping screen. Budgets: full 300 MB import < 60 s (`just test-epg-budget`), window and now/next in `benches/budgets.rs`.
  - `library.rs`: profiles (non-secret settings in `profiles.json`) and the open profile's library (cache-first open, sync that downloads before locking the database, browse, search, play URLs); `m3u.rs`: the streaming M3U parser; `xtream.rs`: the Xtream Codes client and sync; `db.rs`: the profile database, sync and search (`docs/DATA_MODEL.md`); `playback.rs`: buffer presets and the watchdog.
  - `premiumize.rs`: the Premiumize cloud (API v1): folders, transfers, the account check, and the OAuth device login; the token comes from the app with every call (secure storage) and is never stored or logged here. `xtream.rs` also reads a movie's or series' details for its page (`get_vod_info`/`get_series_info`, not stored).
  - `tracking.rs`: Trakt and Simkl: the device login, token refresh a minute before expiry, and scrobble start/pause/stop by cleaned title and year (shows: name, season, episode, via `Library::track_info`); tokens and Trakt's user-owned app come from the app's secure storage with every call.
  - `update.rs`: the in-app updater's checks: the signed `latest.json` from the latest GitHub release against `keys/update-public-key.hex` (compiled in), version compare as numbers, the platform's asset, a download kept only when size and SHA-256 match; tested against the test kit's mock release server.
  - `logos.rs`: the logo disk cache: one file per URL (FNV-1a name) in the cache folder, at most 6 downloads at once, 2 MB cap, failed URLs not retried until restart.
  - Networking: reqwest with rustls on the ring provider (no C toolchain needed for Android/iOS builds), installed once per process.
  - Performance budgets: `crates/gerdtv-core/benches/budgets.rs` (`just bench`).
- `crates/gerdtv-api` (package `gerdtv_api`): the flutter_rust_bridge surface; types, async functions, event streams, no logic.
- `crates/gerdtv-testkit`: synthetic data, mock servers, fault injection, and the repository rule tests (`tests/repo_rules.rs`).
  - The fault server (`crates/gerdtv-testkit/src/fault.rs`) serves a synthetic clip as endless live TS (timestamps and continuity counters rewritten per loop, so it looks like a real channel to mpv), sliding live HLS (optionally with rotating segment URLs) and seekable VOD, and injects drops, stalls, throttling, HTTP status errors, live end of file and cuts of open streams, from Rust (`set`, `once`, `cut`) or over HTTP (`/_fault/…`). Run it by hand with `cargo run -p gerdtv-testkit --example fault_server`; `just test-integration` starts it for the app's integration tests.
  - The libmpv harness (`crates/gerdtv-testkit/tests/libmpv_watchdog.rs`, `just test-harness`): real libmpv (headless) driven by the real watchdog against the fault server, one test per fault (drop, 5xx, stall, live end of file, throttling, HLS with rotating URLs, 403, timeshift rewind), serially (FFmpeg's log callback is process-wide); `just soak` runs 30 min of random faults (nightly).
  - Generators (`crates/gerdtv-testkit/src/generate.rs`): a seeded synthetic library (30 % live, 50 % movies, 20 % episodes, with prefixes, quality tags, umlauts, years and `S01E02` names) as M3U or Xtream Codes JSON, and an XMLTV guide; 150k entries come to about 45 MB of M3U, 2,000 channels × 7 days to about 300 MB of XMLTV (the 6.4 budgets).
  - Mock servers: an Xtream Codes panel over the generated library (`src/mock_xc.rs`; streams redirect to a fault server), Premiumize (`src/mock_premiumize.rs`: cloud, transfers, device login), Trakt and Simkl (`src/mock_tracking.rs`: device login, refresh, scrobbles), TMDB v3 (`src/mock_tmdb.rs`; umlaut-folded search, details, seasons, 401, 429 with `Retry-After`), and the release download URLs (`src/mock_release.rs`; valid, bad signature, bad hash, downgrade, missing platform, server error, signed with a fixed test key).
  - The clip (`crates/gerdtv-testkit/media`) is generated by `crates/gerdtv-testkit/media/generate.sh` (ffmpeg test sources) and committed, so CI needs no ffmpeg.
- macOS update install (`app/lib/platform/mac_install.dart`): `ditto` unpacks the zip, `codesign --verify --deep --strict -R=<installed app's designated requirement>` accepts only our certificate's builds, then `app/assets/update/swap-macos.sh` (detached) waits for the app to quit, renames the old bundle to `gerdTV.previous.app`, copies the new one in (deleting the old one, or restoring it on failure) and opens it; it logs to `swap.log` next to itself.
- `crates/gerdtv-release`: update key generation, `latest.json` assembly, signing and verification (CI and `just verify-release`).

## The seam (Rust ↔ Flutter)
- `app/flutter_rust_bridge.yaml` points the codegen at `crates/gerdtv-api`; `just codegen` writes the Dart side to `app/lib/src/rust`.
- `app/rust_builder` is a Flutter FFI plugin using Cargokit: every Flutter build (Linux, macOS, Android, iOS) compiles `gerdtv_api` for its targets and bundles `libgerdtv_api`.
- Bridge modules: `api/simple.rs` (start-up), `api/playback.rs` (presets, watchdog), `api/update.rs` (`check_update`, `download_update`), `api/logos.rs` (the logo cache: `init_logo_cache` once at start, `logo_file` per URL), `api/library.rs` (profiles; an opaque `Library` per open profile with sync, categories, items, search pages (a section's kinds or one group, with the matching groups) carrying the caller's sequence number, recent searches, play URLs, the guide: sources, refresh, now/next, grid window, programme search, manual mapping). Errors cross as credential-free messages.
- `RustLib.init()` loads the library before the first frame. Widget tests replace it with `RustLib.initMock` and a fake (`app/test/support/fake_core.dart`), so they need no native build.
- Debug: "Failed to load dynamic library" at start means Cargokit didn't build or bundle the library; build with `-v` and look for the Cargokit step.

## The app (Flutter)
- `app/lib/services/session.dart`: the app's state (`ChangeNotifier`): the open profile's `Library`, sync status, and the one player the whole app listens to (`app/lib/player/switch_player.dart`, forwarding mpv's media_kit player or, for live on Apple platforms, the AVPlayer engine) and the `WatchdogAdapter` that drives mpv. `app/lib/services/secrets.dart`: profile secrets in `flutter_secure_storage` (macOS: the legacy keychain, which needs no provisioning profile). `app/lib/services/search_model.dart`: numbered search queries per search field (a section or a group), stale answers dropped.
- Screens in `app/lib/screens`: setup (first run), shell (rail/bottom bar), browse/items/episodes, the section search, player, settings.
- Cleartext HTTP (providers use plain HTTP on a user-entered host): allowed in ATS on iOS/macOS for AVPlayer (the core's local HLS on 127.0.0.1, or a provider's own HLS played directly). Android needs no setting: the core (sync, guide, logo cache, updater) and libmpv use their own networking, and Flutter itself fetches nothing.

## Playback pipeline
- One media_kit `Player` for mpv (live on Apple platforms: the AVPlayer engine below). The Rust core owns the policy (`crates/gerdtv-core/src/playback.rs`): `mpv_options` turns a buffer preset into mpv options, and `Watchdog` turns player events into commands. The Dart adapter (`app/lib/player/watchdog_adapter.dart`) sets the options through media_kit's `NativePlayer.setProperty` before `open()`, feeds position/buffering/completed/error events in, ticks it once a second, and runs its commands (reload, show/hide "Reconnecting (n)").
- AVPlayer engine (live on iOS and macOS): `Library::start_local_hls` starts `crates/gerdtv-core/src/hls.rs`, which reads the channel's TS, cuts ~2 s segments at keyframes (PAT/PMT first), keeps the timeshift window on disk (`timeshift_options`' budget) and serves a live playlist on 127.0.0.1 with a random port and path token; drops and stalls reconnect there with backoff (1 … 10 s) and reach AVPlayer as `#EXT-X-DISCONTINUITY`, 401/403/404 stop it with the watchdog's message. The plugin `app/packages/gerdtv_avplayer` (one Swift source, `darwin/`) plays it with AVPlayer into a Flutter texture plus an `AVPlayerLayer` for PiP; `app/lib/player/av_player.dart` presents it as a media_kit `PlatformPlayer` (position = AVPlayer's time, buffer = the seekable end, i.e. live), so media_kit's controls, the timeshift bar and the now-playing bar work unchanged; an AVPlayer error moves the channel to mpv for the run.
- Watchdog rules (`Watchdog`, table-tested): a live end of file, an error, or no progress for max(15 s, target + 10 s) while not paused by the user (also stuck buffering, or a stream that never starts) schedules a reload with backoff 1, 2, 4, 8, 15, 30 s; while waiting, playing out the remaining buffer doesn't count as recovered; after 3 failed reloads live switches between `.ts` and `.m3u8` (and back), and the form that then plays is remembered per channel; a wake after the app was frozen for 5 s or more (sleep, suspended; seconds since the adapter's last tick) and a network change reload live at once, a return from the background where it kept playing doesn't; FFmpeg's "HTTP error 401/403" stops with a message (no retry loop); audio-output errors are ignored; VOD reloads resume at the last position and give up after 6 attempts; every recovery episode (trigger, attempts, recovered, seconds) goes to `stream_health`.
- Buffer per stream: the item's own preset, else the profile's (`Library::buffer_for`); the demuxer size uses the channel's last measured bitrate (mpv `video-bitrate`, stored per channel and applied while playing as soon as it is known). Adaptive mode lives in the watchdog (more than 3 rebuffers in 600 s → `RaiseBuffer`, at most once per window); the session stores the raised preset as the channel's override.
- Timeshift budget: mobile and desktop have no free-space query yet, so the back buffer assumes a disk budget (16 GB desktop, 4 GB phone/TV) of which `timeshift_options` takes at most a quarter.
- media_kit details the adapter relies on: create players with `WatchdogAdapter.playerConfiguration` (mpv log level warn: FFmpeg reports HTTP status errors as warnings, and media_kit's `error` stream only carries FFmpeg errors starting with `tcp:`); mpv's own "Failed to open <url>" messages contain the URL, so they're classified but never logged.
- Option mapping (names verified in mpv 0.40 and FFmpeg 7.1, and limited to ones mpv 0.36 / FFmpeg 6.0 also have):

| Preset setting | mpv option | Value |
|---|---|---|
| target buffer | `cache-pause-wait`; `cache-secs`, `demuxer-readahead-secs` | the preset's seconds (2 / 8 / 30 / 90 / 1–300); reading ahead 5 s further, else mpv waits for data the demuxer stopped fetching |
| start and resume only with a full buffer | `cache`, `cache-pause`, `cache-pause-initial` | `yes` |
| demuxer size | `demuxer-max-bytes` | target × bitrate × 1.5, at least 32 MiB (bitrate estimate 8 Mbit/s until known) |
| large buffers on disk | `cache-on-disk` | `yes` from 30 s |
| transport reconnect | `stream-lavf-o` | `reconnect=1,reconnect_streamed=1,reconnect_on_network_error=1,reconnect_delay_max=5` |
| network timeout | `network-timeout` | 10 s |

- media_kit's own start-up defaults that stay: `demuxer-lavf-o` (HLS segment retries, allowed extensions), `demuxer-max-back-bytes` (32 MiB until timeshift sets it).
- Timeshift (`timeshift_options`): back buffer `demuxer-max-back-bytes` = window × bitrate (60 min desktop, 30 min phone/tablet/TV), at most a quarter of the free disk, on disk in the app's cache folder (`cache-on-disk` + `demuxer-cache-dir`; embedded libmpv has no default cache folder, so without one it stays in RAM), `force-seekable` and `demuxer-seekable-cache` so rewinding live stays inside the cache. "Behind live" = the live edge (the newest `demuxer-cache-time` before a pause or rewind, plus the time since) minus the position.
- Headless test runs set `ao=null`: with no audio device and no video controller, mpv would end the file at once.

Player engine (Settings → Playback, `app/lib/platform/engine.dart`): media_kit's default library or gerdTV's own build. media_kit's Linux video plugin links `libmpv.so.2` itself, and two libmpv copies in one process crash, so the whole process must load the own build: the choice is a marker file in the support folder (`player-engine-gerdtv`), and `app/linux/runner/main.cc` restarts gerdTV once before Flutter starts with `lib/gerdmpv/` (links `libmpv.so.2`, `libmpv.so` → `libgerdmpv.so`) first in `LD_LIBRARY_PATH`. A change applies after a restart. On Android the video plugin only hands media_kit a surface, so the app picks the library at start (`startEngine`): media_kit opens `libgerdmpv.so` instead of its `libmpv.so`, and FFmpeg inside it gets the JavaVM from media_kit's helper (`av_jni_set_java_vm`) for MediaCodec; APKs that bundle it are built with `--dart-define=GERDTV_OWN_LIBMPV=true`. On macOS and iOS media_kit's video plugin is vendored (`third_party/media_kit_video`, `third_party/README.md`): it calls libmpv through `MPV.swift`, which looks the functions up in the library named by the `GERDTV_LIBMPV` environment variable (set by `startEngine` before media_kit starts; media_kit's `Mpv.framework/Mpv` without it), so each mpv handle meets only its own library; GerdMpv is in the app but loaded only when chosen. CI builds the Apple library when its script changes and plays the clip with the macOS slice before caching it. CI builds the Android library when its scripts change (cached) and plays the testkit's clip with it on an x86_64 emulator before caching it (`scripts/test-libmpv-android.sh`, `scripts/ci-android-emulator.sh`). CI builds the own Linux library when the script changes (cached) runs the libmpv harness on both engines and the integration tests on the own one only (`just test-harness-gerdmpv`, `just test-integration-gerdmpv`): the system libmpv's Lua scripts sometimes deadlock media_kit's start in CI, and the own build has no Lua.

All are pulled in through `media_kit_libs_video`; LGPL builds combine fine with the GPL-3.0 app. The in-app Licences screen lists them (`app/assets/licences/native.txt`, kept in step with this table by hand) and every bundled Rust crate (`app/assets/licences/rust.txt`, written and checked by `scripts/licences.sh`; `app/lib/licences.dart`).

## Desktop windows
`app/lib/platform/mini_window.dart` switches the main window into mini-player mode (480 × 270, hidden title bar, always on top, on all Spaces) and restores its bounds. A second window would be a second Flutter engine that can't share the media_kit player, so the stream would reopen.

## Platform channels
- `gerdtv/platform` (Android: `app/android/app/src/main/kotlin/world/zakis/gerdtv/MainActivity.kt`, Dart: `app/lib/platform/platform_bridge.dart`): Dart reports playback start/stop (`setPlaying`) and hands a downloaded update APK to the system's installer (`installApk`, shared through a FileProvider over the cache folder), and Settings → Account → Your data writes its export into Downloads (`saveToDownloads`, MediaStore on Android 10+); `brightness`/`setBrightness`/`resetBrightness` serve the player's brightness swipe (Android: the window's own); `openUrl` opens a web page (Android `ACTION_VIEW`, false without a browser; iOS `UIApplication.open`; desktop runs `open`/`xdg-open` from Dart); Android enters Picture-in-Picture when the user leaves while playing (auto-enter on Android 12+, `onUserLeaveHint` before) and reports `pictureMode`, which makes the player show only the picture. While playing, `PlaybackService.kt` runs as a foreground service (type mediaPlayback) with a notification, a partial wake lock and a Wi-Fi lock, so playback continues with the screen off.
- The same channel on iOS (`app/ios/Runner/AppDelegate.swift`): the audio session is `.playback` and `UIBackgroundModes` has `audio`, so sound continues with the screen locked or in another app. Picture-in-Picture of mpv's picture: while mpv plays (`preparePip`), the vendored media_kit hands every drawn frame to an `AVSampleBufferDisplayLayer` behind the Flutter view (`TextureHW.pipSink`), the PiP content source, which starts by itself on Home; in the background mpv renders it in software at PiP size (`TextureHW.useSoftware`; no GL there; without PiP nothing is drawn). The window's play/pause and skip come back as `pipCommand`, its range from `pipState`. The video views don't pause when the app leaves the foreground (`playerVideo`), so sound goes on with the screen locked. The CI macOS job compiles the iOS app on every PR.
- `gerdtv/avplayer` (`app/packages/gerdtv_avplayer/darwin/Classes/GerdtvAvPlayerPlugin.swift`, Dart: `app/lib/player/av_player.dart`): open/play/pause/seek/volume/rate/buffer/tracks/PiP for the AVPlayer engine; `state` every 0.25 s. In the iOS background without PiP its layer lets go of the player, or iOS would pause it.
- `setLogo` on the same channel switches the app icon to a logo from `app/lib/screens/app_logo.dart`. Android enables that logo's launcher `<activity-alias>` and disables the others (`DONT_KILL_APP`). iOS calls `setAlternateIconName` with the asset catalog set `AppIcon-<name>`, and the default logo is the primary icon. macOS (`app/macos/Runner/MainFlutterWindow.swift`) sets the Dock icon and Linux (`app/linux/runner/my_application.cc`) the window icon from PNG bytes Dart renders, again at every start.
- macOS menu bar mode (`app/macos/Runner/MainFlutterWindow.swift`, Dart: `app/lib/platform/menu_bar.dart`): `setMenuBar(enabled, labels)` adds an `NSStatusItem`; with it on, `MainFlutterWindow.close` only hides the window and `AppDelegate.applicationShouldTerminate` turns the Dock's Quit and Cmd-Q into hiding (activation policy accessory), except for the menu's Quit and the system's logout, restart and shutdown (the quit event's `kAEQuitReason`); the menu's Play/Pause and Stop call back `menuBar`.
- `voiceAvailable` and `listen` on the same channel (Android only): the search field's mic starts the system's speech recognizer (`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`, answered in `onActivityResult`); the recognizer records, so gerdTV holds no microphone permission. The manifest's `<queries>` lets `voiceAvailable` see whether one is installed; without one the mic doesn't show.
